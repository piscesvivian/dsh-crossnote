# Markdown include/transclusion tools — prior-art research

Research question: find existing tools/syntaxes that let a "master document" (总纲) include many other Markdown files (or a *named heading section* of a file), with heading-level demotion, alias/renaming of chapters, correct relative image/link resolution, a `.mdx`-like custom suffix for the aggregator, and a single standalone `.md` output that Typora can open and export to PDF.

Method: primary sources (official docs, GitHub READMEs, source code) fetched 2026-11-25. All claims below cite a source URL. `unknown` means I could not verify the feature in a primary source during this research.

## 1. Feature comparison table

## 2. Verdict per tool (fit for this use case)

Requirements recap: `.mdx`-like custom suffix for the master doc; named-section include; heading demotion by ≥1; alias/rename of included chapters; image/link rebasing; single standalone `.md` for Typora; minimal extra software.

1. **Pandoc + pandoc-include — strong fit (best immediate path).** Has `incrementSection` heading demotion and `rewrite-path` image rewriting, supports partial include by line/snippet, and Pandoc writes plain markdown for Typora. Needs Pandoc + a Python filter installed; no named-heading include and no alias/rename documented. ([README](https://raw.githubusercontent.com/DCsunset/pandoc-include/master/README.md))
2. **Pandoc + custom Lua filter — strongest long-term fit.** Pandoc has a built-in Lua 5.4 filter API (no external dependencies) where `Header.level` demotion, `Image`/`Link` rebasing, section extraction, alias handling and markdown output can all be implemented in one script — ideal for a custom `.mdx`-style master syntax. Requires writing that filter. ([Lua filters](https://pandoc.org/lua-filters.html))
3. **@it-service-npm/remark-include — strong prior art.** Unique combination of *automatic* heading demotion, recursive/glob includes, and relative image+link rewriting, with plain `.md` output via remark-stringify. Missing named-section include and alias/rename; needs Node.js. ([README](https://raw.githubusercontent.com/IT-Service-NPM/remark-include/master/README.md))
4. **MarkdownPP — good conceptual prior art, weak tooling.** `!INCLUDE "file", 2` demotion and `.mdpp` → `.md` CLI match the custom-suffix + merged-output idea exactly, but no section include/rebasing and stale Python tooling. ([readme](https://raw.githubusercontent.com/jreese/markdown-pp/master/readme.mdpp))
5. **python markdown-include — moderate.** `inheritHeadingDepth` + `headingOffset` give demotion, but output is HTML and no section include/rebasing. ([README](https://raw.githubusercontent.com/cmacmackin/markdown-include/master/README.md))
6. **@mdit/plugin-include / VuePress markdown-include — moderate.** Line ranges and `#region` includes plus image/link rebasing; no heading demotion or named-heading include; HTML output only (not standalone `.md`). ([docs](https://mdit-plugins.github.io/include.html), [VuePress](https://ecosystem.vuejs.press/plugins/markdown/markdown-include.html))
7. **Diplodoc — moderate.** One of the few with true *named-section* include (`file.md#part`) and relative-link rebuilding; but tied to the YFM/Diplodoc build toolchain, heading demotion unknown. ([docs](https://diplodoc.com/docs/en/syntax/includes))
8. **Obsidian — poor for output.** Best-in-class *authoring* section transclusion (`![[Note#Heading]]`, [help](https://obsidian.md/help/embeds)) but proprietary syntax that other viewers/Typora show literally, no demotion or link rebasing; Typora itself has an open feature request for transclusion ([issue #441](https://github.com/typora/typora-issues/issues/441)).
9. **mdBook — poor fit beyond design inspiration.** `{{#include}}` with ANCHOR regions and a pluggable preprocessor pipeline ([docs](https://rust-lang.github.io/mdBook/format/mdbook.html), [preprocessors](https://rust-lang.github.io/mdBook/format/configuration/preprocessors.html)), but built for an HTML book, no heading demotion/section-by-heading, and no standalone `.md` export.
10. **MDX / Docusaurus — poor fit.** File imports are JavaScript ESM and compilation to JS is mandatory ([MDX docs](https://raw.githubusercontent.com/mdx-js/mdx/main/docs/docs/using-mdx.mdx), [Docusaurus docs](https://docusaurus.io/docs/markdown-features/react)); output is JSX/JS, not a `.md` Typora can open.
11. **remark-directive — infrastructure only.** Parses directives but "Doesn't handle the directives: create your own plugin" ([readme](https://raw.githubusercontent.com/remarkjs/remark-directive/main/readme.md)).
12. **pandoc-crossref — irrelevant** to inclusion (figure/table/equation numbering only) ([docs](http://lierdakil.github.io/pandoc-crossref/)).
13. **Qard/remark-include, VS Code Markdown Include, GNU m4, python markdown-include, GitBook/MarkdownPP-era plugins** — each only partially satisfy the matrix and are stale or too low-level; useful as syntax references only.

## 3. Top-3 most relevant prior art

1. **Pandoc + pandoc-include** — closest turnkey match: include syntax, `incrementSection` demotion, `rewrite-path` image rewriting, `.md` export. ([README](https://raw.githubusercontent.com/DCsunset/pandoc-include/master/README.md))
2. **@it-service-npm/remark-include** — closest *feature-complete* match: auto heading-level inheritance/demotion, recursive/glob include, image+link rebasing, `.md` output. ([README](https://raw.githubusercontent.com/IT-Service-NPM/remark-include/master/README.md))
3. **Pandoc Lua filters** — the implementation substrate for a custom `.mdx` master syntax: built-in Lua API to implement named-section extraction, demotion, alias/renaming, image/link rewriting and markdown output in one filter with no separate toolchain. ([Lua filters](https://pandoc.org/lua-filters.html))

Runner-up: **MarkdownPP** for its `.mdpp → .md` custom-suffix + heading-shift design ([readme](https://raw.githubusercontent.com/jreese/markdown-pp/master/readme.mdpp)).

## 4. Gap analysis for the target design

None of the surveyed tools covers all requirements simultaneously:

- **Named-heading section include** is found only in Obsidian (`![[Note#Heading]]`, [help](https://obsidian.md/help/embeds)), Diplodoc (`file.md#part` with `{#part}` anchors, [docs](https://diplodoc.com/docs/en/syntax/includes)), and region-marker substitutes (`#region` in @mdit/plugin-include, `ANCHOR:` in mdBook) — not heading-name-based extraction into a standalone `.md`.
- **Heading demotion** exists in pandoc-include (`incrementSection`), MarkdownPP (`, 2` suffix), remark-include (auto), python markdown-include (`inheritHeadingDepth`/`headingOffset`), and MDX (`components`), but never bundled with named-section include + standalone `.md` output.
- **Alias/rename of included chapters or output directories** is not documented in any surveyed tool (`resolvePath` in @mdit/plugin-include is a path alias, not a chapter-title rename; `{{#title ...}}` in mdBook renames a chapter page title only, [mdBook docs](https://rust-lang.github.io/mdBook/format/mdbook.html)) → unknown across the board.
- **Relative image/link rewriting** exists in pandoc-include (images), @mdit/plugin-include, @it-service-npm/remark-include, and Diplodoc — but a full combined solution still needs custom work.
- **Typora-compatible single `.md`** is directly supported by Pandoc and remark-stringify; Typora has no native transclusion ([issue #441](https://github.com/typora/typora-issues/issues/441)) so a pre-build/merge step is unavoidable.

Conclusion: build a small custom pipeline (a Pandoc Lua filter or a Node/remark script) that parses a custom `.mdx`-style master file, extracts named heading sections from source files, shifts `Header.level`, rewrites `Image`/`Link` paths, applies chapter aliases, and writes one merged `.md` for Typora. Pandoc + Lua is the leanest option (single binary, no separate toolchain); remark-include is the best reference implementation for demotion and path rebasing semantics.
